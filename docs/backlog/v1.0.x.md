### v1.0.0: Maturity Gate

**Goal**: Other people log in. The version bump marks the review that says the instance is ready for them — no new features ship here by design.

**Context**: The major-version bump is reserved for "the v1.0 feature set is complete" (version-management rule); this milestone defines *complete* as a readiness review over work that already shipped, so the gate can't silently accumulate scope.

**Persona**: the invited tester (their first hour is the acceptance test); the operator (their confidence is the ship criterion).

**Key Design Decisions**:
- **No feature epics live here** — anything discovered during gate review that needs building goes to the appropriate 0.x series (or a Post-Deploy Revision of the milestone that owns it), keeping the gate a review, not a milestone-of-last-resort.
- **Production restarts from a fresh database at (or before) this gate** (policy, 2026-07-27) — all pre-gate prod data is re-derivable (external services) or exportable (workflows); consequently **0.x work treats backward compatibility as best-effort only** — migrations must be *correct* wherever they run (house rule), but preserving pre-gate prod data through breaking model changes (e.g. v0.12.x artists/albums) is not a design constraint unless breakage is severe. The final pre-invite re-import runs everything through current machinery, so testers meet a dataset with full provenance from birth.

#### Gate Epics

- [ ] **Gate Review & Door Opening**

    **Story**: The operator wants a deliberate, documented moment of "ready" — every promise the product makes to a stranger verified — before the first invite goes out.

    **Spec** (the readiness checklist):
    - All 0.x series through v0.15.x confirmed `✅ Completed` (user-confirmed stability, not just shipped)
    - Sovereignty verified live: a real archive exported to user-controlled storage and round-tripped into a fresh instance ([v0.15.0](v0.15.x.md))
    - Onboarding verified live: a fresh account completes signup → connect → import → schedule self-serve ([v0.15.1](v0.15.x.md))
    - [PDR-001](../decisions/PDR-001-data-ownership-model.md) posture review: the ownership story is real, evidence ledger current
    - [PDR-002](../decisions/PDR-002-multi-user-scale-posture.md) posture review: abuse/scale stances actioned or explicitly accepted (BYPASSRLS, quotas, cache posture)
    - RLS isolation spot-checks against the production database
    - First invites sent; registration remains invite-only

    **Tests**:
    - (manual) the checklist — every line has evidence linked before the version tag is cut

    Effort: S | Dependencies: v0.15.x complete | Status: Not Started

- [ ] **Identity substrate clean-break deletions**

    **Story**: The fresh database is the one moment the track identity substrate can shed columns that exist only to protect pre-gate data. Recorded 2026-09-15 ([track-stack review](../backlog/track-stack-review-2026-09-15.md), P7) so the moment is not missed.

    **Decisions**:
    - **Identity lives only in mappings** *(shipped v0.12.0.2 for spotify_id/mbid; uq_tracks_user_isrc remains)* — drop `tracks.spotify_id` / `tracks.mbid` and `uq_tracks_user_{isrc,mbid,spotify_id}` (memo FM2b); deletes `_sync_promoted_denormalized_ids`, `_clear_denormalized_id`, `count_stale_denormalized_ids`, migration 044's repair pass and the `save_track` upsert ladder (~300 lines, 32 read sites). Prerequisite: the resolve-and-record service (v0.12.1 pre-flight) and a measured cost for `get_existing_identity_mappings` via join instead of column.
    - **One supersession writer** — route `merge_mappings_to_track`'s raw CTE through `assert_mappings(reason="conflation")`.
    - **No column without a reader** — drop `track_mappings.supersession_scope` (only ever written `NULL`) and `next_verify_at` (no reader) unless a writer/reader has appeared by then.

    **Tests**:
    - characterization suite + the v0.10.3 zero-delta re-import guarantee, on the fresh database

    Effort: L | Dependencies: fresh database (this gate); v0.12.1 pre-flight | Status: Not Started
