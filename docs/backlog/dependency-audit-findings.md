# Dependency Audit — Findings

**Status**: Active — work orders W1–W10 unscheduled.

> Docs-first pass from the [v0.8.17 sweep closeout](v0.8.13-0.8.17.md#v0817-sweep-closeout--ratchet--review) (2026-07-02, branch `sweep-closeout-v0.8.17`), sibling to the v0.8.12 code audit: every dependency **necessary**, on the **best-supported option** for its job, and **fully utilized** rather than shadowed by bespoke code. No runtime changes ship with this doc — each actionable finding is a work order at the bottom, scheduled separately.

**Scope**: `pyproject.toml` (21 runtime + 12 dev), `web/package.json` (21 runtime + 20 dev), root `package.json` (1 dev). Tools: `uvx deptry .`, `pnpm --prefix web lint:dead` (knip), `uv pip list --outdated`, `pnpm outdated`, targeted usage greps.

**Verdict in one line**: the tree is healthy — zero unused runtime deps on either side, versions current to within patch/minor releases — with two unwired dev tools, one undeclared transitive in production code, and a handful of utilization/posture gaps, all small.

## Lens 1 — Necessity (is it used at all?)

**Backend runtime (21/21 used).** deptry flags three `DEP002` "unused" that are all module-name false positives, paired with their own `DEP001` counterparts: `python-dotenv` → imported as `dotenv` (`src/config/settings.py:24`), `pyjwt` → imported as `jwt` (`src/interface/api/auth_gate.py:19`), `python-multipart` → never imported by us at all, but FastAPI requires it at runtime for `UploadFile`/form parsing (`src/interface/api/routes/imports.py`). A `[tool.deptry.package_module_name_map]` would silence all three if deptry is adopted (→ W7).

**The one real deptry hit — `starlette` is imported but undeclared.** Three ASGI middleware modules import it directly (`auth_gate.py`, `caching.py`, `security_headers.py` — `starlette.datastructures` + `starlette.types`; FastAPI does not re-export these). We depend on it only transitively via `fastapi`, so a future fastapi bump can move starlette under our feet with no resolver signal. Declare it explicitly (→ W1).

**Backend dev (10/12 wired, 2 dead).**

**Web (41/41 used).** knip exits clean — no unused dependencies, exports, or files. Root `package.json`: `concurrently` drives the `pnpm dev` orchestration line. All necessary.

## Lens 2 — Modernity & support

**Backend**: everything current. `uv pip list --outdated` shows only patch/minor lag: coverage 7.14.3→7.15.0, croniter 6.2.2→6.2.3, pydantic-core 2.46.4→2.47.0, stevedore 5.8.0→5.9.0, typing-extensions 4.15.0→4.16.0 — all transitive or trivial, none urgent. Core stack (SQLAlchemy 2.0.51, FastAPI 0.139, Starlette 1.3.1, pydantic 2.13.4, structlog 26.1) is the maintained mainline for each job; no dep is superseded or abandoned.

**Web**: `pnpm outdated` shows only `@biomejs/biome` 2.5.1→2.5.2 and `lucide-react` 1.22→1.23. Current.

**Forward signals (watch items, carried from the v0.8.14/15 bumps + this closeout):**

1. **Starlette 1.3 deprecates `httpx` under its TestClient in favour of `httpx2`** — our full suite emits 15 `StarletteDeprecationWarning`s today via `fastapi.testclient`. Production connector code on `httpx` 0.28 is unaffected (the deprecation is TestClient-scoped). Plan the test-client migration before Starlette hard-removes it (→ W4).
2. **`@neondatabase/auth` is `0.4.2-beta`** (latest published) and drags ~95 lockfile entries of deprecated `@react-email/*` transitives (auth email templates). The pathway is still the right one — it's the vendor SDK for Neon Auth — but it's a beta pinned exactly; track GA and re-audit the transitive tail at that bump (→ W8).
3. **Playwright browser↔baseline coupling** (proven this closeout, see supply-chain below): the CI container tag must equal `@playwright/test`'s version or the e2e gate dies at browser launch — and every Playwright bump requires regenerating visual baselines in the new image. Bump package + CI image + baselines as one unit (procedure in `web/e2e/README.md`; now also on CLAUDE.md's version-bump bar).
4. **PyPI name collision**: `uv pip list --outdated` reports our local `mixd 0.8.16` as "outdated" vs an unrelated **`mixd 1.2` on PyPI**. Harmless today (we never install from PyPI), but it's a latent dependency-confusion footgun for any future `pip install mixd` in CI or docs (→ W9).

## Lens 3 — Utilization vs bespoke (are we reimplementing what a dep gives us?)

- **tenacity** — properly used for connector retry/backoff (`base.py` + 3 connector clients). **One hand-roll found**: `base_repo.py` catches "concurrent operations are not permitted" and retries with a bare `await asyncio.sleep(0.1)` loop — tenacity-shaped logic without tenacity's jitter/limits/logging (→ W3). The other `asyncio.sleep` sites audited are honest non-retries: the MusicBrainz 1 req/s throttle (rate-limit policy, not retry), poll/progress loops (`periodic_loop.py`, SSE/progress code).
- **rapidfuzz / jellyfish** — each used exactly where it should be (`matching/algorithms.py` fuzzy scoring; `text_normalization.py` phonetics). No bespoke string-distance code found; the pair is complementary, not redundant.
- **croniter** — correctly caged: one import (`schedule_timing.py`), the v0.8.2 decision (internal DST-correct next-occurrence math only, no user-facing cron) holds.
- **orjson** — wired as the psycopg JSONB serializer (`db_connection.py`, deliberate, documented in-module). **Not** wired as FastAPI's response class. *(Corrected 2026-07-31 by W6's measurement: the "API responses still serialize via stdlib json" claim recorded here was already stale — since the FastAPI 0.140 upgrade they serialize via Pydantic's Rust core, which is faster than routing them through orjson. See W6.)*
- **pydantic** — API schemas + settings only, as designed; domain stays attrs-frozen. No bespoke validation shadowing it found.

## Supply-chain posture (documented, not fought)

- **Security-floor overrides** live in **`web/pnpm-workspace.yaml`** (not the repo root — the v0.8.17 spec's root-path reference was off by a directory): `hono >=4.12.7`, `fastify >=5.8.3`, `defu >=6.1.5`, `picomatch >=4.0.4`, migrated from `package.json` `pnpm.overrides` for pnpm 11.5+.
- **pnpm 11.5's lockfile supply-chain verification is active** — observed during this closeout's container installs: "Verifying lockfile against supply-chain policies (890 entries)". The release-age cooldown that deferred four <24h-old releases at the v0.8.15 bump is pnpm's built-in policy behavior, **not** an explicit repo setting — `pnpm config get minimumReleaseAge` is unset. Making it declarative in `pnpm-workspace.yaml` would pin the posture against pnpm default changes (→ W5).
- **Every Dependabot job had been failing for two months** (found and fixed 2026-07-27). `.gitmodules` pinned `docs/dev-setup-guide` at `c291182`, a commit that was never pushed to its own remote. Dependabot clones with `--recurse-submodules`, so its clone aborted (`job_repo_not_found`) and the `update_graph` job failed on every run from **2026-05-10**; CI never noticed because `actions/checkout` here sets `submodules: false`. Drift at discovery: **39 wrong versions, 10 packages missing, 56 stale extras**, and 17 "open" Python alerts describing already-patched CVEs. Fixed by pushing the missing commit — a fast-forward on the submodule's `main`. **Diagnostic lesson worth keeping**: the symptom (a stale SBOM) invites theories about GitHub's undocumented `uv.lock` parser, but `gh run list --workflow "Dependency Graph"` showed the real cause in one command; check whether the producing job runs before reasoning about what it produces. The standing guard is `scripts/check_dependency_graph.py` (weekly, `.github/workflows/dependency-graph.yml`), which compares the graph against `uv.lock` and is indifferent to the cause of any divergence. Details in [docs/development.md](../development.md#dependency-security).
- **Playwright image pinning** is part of this posture: the CI container (`mcr.microsoft.com/playwright:v1.61.1-noble`) is the only sanctioned browser build for visual baselines; treat its tag as a locked dependency coupled to `@playwright/test` (see Lens 2, signal 3).

## Work orders

Each schedules independently (revision or later version); none gate the v0.8.17 ship.

- **W1 (XS, done 2026-07-31)** — `starlette>=0.46.0` declared in `pyproject.toml` runtime deps, floor mirroring fastapi 0.140.2's own `starlette>=0.46.0` rather than inventing a tighter one (mcp and sse-starlette already pull resolution to 1.3.1). No lock churn beyond the new `requires-dist` row. Correction to this finding: the direct imports are in **6** modules, not the 3 recorded above — `src/interface/mcp/http.py` and `src/interface/api/oauth/routes.py` import starlette too. Landed with W7, which now guards it.
- **W2 (XS, done 2026-07-31)** — `interrogate` and `bandit` removed (both unwired; ruff `S` covers bandit's surface), taking 4 transitives with them. The dead `# nosec B311` went from `shuffle.py` *and* `selecting.py` — bandit was its only reader. Correction to the work order: the `# ruff:ignore[…]` on the same `shuffle.py` line is **not** a fossil and stays — it is ruff 0.15.22's current spelling (RUF105 migrated `# noqa: CODE` to it) and removing it makes S311 fire.
- **W3 (S, done 2026-07-31)** — The bare `except`/`asyncio.sleep(0.1)` loop in `base_repo.py` is now `concurrent_session_retry()`, a named tenacity policy in a new `persistence/repositories/_shared/retry_policies.py`. Semantics preserved exactly: 2 attempts, fixed 0.1s (the old loop had no jitter either), same substring match, same warning log, `reraise=True` so the DB exception reaches the caller rather than `RetryError`. **Not** reused from `connectors/_shared/retry_policies.py`: that factory is built on `ErrorClassifier`, httpx2 exception types, and per-service `settings.api.*`, none of which exist for a DB call — and importing `connectors/` from `persistence/` would cross subsystems. Regression test is integration (`test_base_repo_retry.py`), and it captures SQLAlchemy's *own* error string at runtime rather than hardcoding it, so a future wording change fails the test instead of silently disabling the retry.

    Carried forward, unfixed and deliberately so: the guard wraps only `execute_select_one` (6 call sites) — `_execute_query`, `find_one_by`, `get_by_ids`, `upsert`, and the bulk paths have no concurrent-session protection at all; and the fixed no-jitter backoff makes colliding coroutines retry in lockstep, which is the exact case that produces the error. Both predate this refactor and widening them is a behaviour change, not a port.
- **W4 (S, done 2026-07-30)** — Migrated to `httpx2` repo-wide (52 imports across `src/`, `tests/`, `scripts/`), not just the test client: `encode/httpx` has had no release since 2024, Starlette 1.3's TestClient already prefers `httpx2`, and mcp v2 requires it — so the mixed state, not the migration, was the risk. `httpx` now appears in the lock only as an `anthropic` transitive. The 15 deprecation warnings are gone.
- **W5 (XS, done 2026-07-31)** — `.github/dependabot.yml` sets `cooldown: default-days: 7` on every ecosystem (2026-07-27), and `web/pnpm-workspace.yaml` now states `minimumReleaseAge` explicitly so it survives a pnpm default change. **The 7-day parity this order asked for is not achievable and was not taken.** pnpm 11 enforces the setting as a *lockfile* policy on every install including `--frozen-lockfile`, not just on new resolutions: at 10080 minutes the committed lockfile failed verification on 84 entries the day after the orval 8.23 / radix-ui sweep, which would red every CI job and the Docker build until the window passed. Settled at 1440; Dependabot's cooldown still governs the automated path. Rationale lives in `pnpm-workspace.yaml`.
- **W6 (XS-S, done 2026-07-31 — measured, not adopted)** — Benchmarked and **rejected**; the order's premise predates FastAPI 0.140. FastAPI now serializes response models straight to bytes via Pydantic's Rust core, and `default_response_class=ORJSONResponse` *replaces the `DefaultPlaceholder` that selects that path* (`fastapi/routing.py`), reverting to serialize → dict → `orjson.dumps`. Measured **0.80–0.95× (slower)** end-to-end at 200–10,000 rows on `/playlists/{id}/tracks`, worst on the 3 MB response; `ORJSONResponse` is itself `@deprecated` in 0.140. Encoding is only 9–25% of in-process cost — the dominant term is Pydantic schema construction (117 ms vs 13.5 ms to encode, at 10k rows). **If that endpoint ever gets hot, the lever is its unbounded `limit=10000` default** — `web/src/pages/PlaylistDetail.tsx` requests whole playlists with no params — not the JSON encoder. Also noted in passing: `CachingMiddleware`'s ETag MD5 costs 3.5 ms on that same 3 MB body. `orjson` keeps its existing justification as the psycopg JSONB serializer.
- **W7 (S, done 2026-07-31)** — `uvx deptry .` runs as the "Dependency check" step in CI's Python job, after vulture and before the test step; config in `pyproject.toml` `[tool.deptry]`. Exits clean on 530 files. Three notes for the next reader: (a) use `extend_exclude`, never `exclude` — overwriting it drops deptry's defaults, including `tests`, whose dev-only imports then trip 234 DEP004s; (b) the `package_module_name_map` (dotenv/jwt/multipart) is mandatory under `uvx`, not belt-and-braces — uvx runs deptry in its own isolated env, so it can never read our installed metadata to infer import names, and each unmapped mismatch surfaces as a bogus DEP002/DEP001 pair; (c) the one sanctioned suppression is `per_rule_ignores.DEP002 = ["python-multipart"]` — a genuine false positive, since base `fastapi` needs it at request time for `UploadFile` parsing and no import graph can see a runtime plugin. Also documented in [docs/development.md](../development.md#dependency-security).
- **W8 (watch, re-verified 2026-07-27)** — `@neondatabase/auth`: bump at GA, re-audit the `@react-email/*` transitive tail then. Still `0.4.2-beta` (latest published), still exact-pinning `better-auth: "1.4.18"`, so its 9 open alerts — one critical — remain unfixable from our side. All of them target server-side surfaces (oidc-provider, mcp/organization plugins, OAuth token endpoints, admin/SCIM); `web/src/api/auth.ts` is a pure client against Neon's hosted auth server, so none is reachable. Rationale lives in `web/pnpm-workspace.yaml` next to the overrides.
- **W9 (XS, done 2026-07-31)** — Callout at the top of `docs/deployment.md`. Verified the collision: PyPI `mixd` is an unrelated Cloudflared tunnel dev-server (`mixddev1391`, v1.2, 2025-08), so `pip install mixd` silently installs someone else's package.
- **W10 (S-M, partly done 2026-07-31 — CI step deliberately NOT wired; needs a decision)** — `import-linter>=2.13` installed, five contracts encoded in `[tool.importlinter]`, 43 `ignore_imports` entries each traced to the rule file that sanctions it. **Result: 3 contracts kept, 2 broken — 22 direct edges across 16 modules that no rule file sanctions.** The v0.8.12 claim that enforcement was "already in place" was wrong in both directions: nothing was installed, *and* the architecture does not currently satisfy its own documented contract.

    The CI step is **held back on purpose** — adding it today reds every build until the 22 edges are resolved, and that resolution is a fix-vs-sanction judgement per edge, not mechanical work. `uv run lint-imports` works locally now, so the gap is visible and measurable; wiring CI is the last step, after the decisions below.

    Three things this surfaced that are worth more than the contract itself:
    - **~80 modules were invisible to any import analysis.** grimp skips directories without `__init__.py`, so `infrastructure/persistence/` (all repositories, `db_models`, `db_connection`), `application/services/`, and `domain/services/` were unenforceable namespace packages. Adding three docstring-only `__init__.py` files took the graph from 392 to 473 modules. Any prior claim of layer enforcement could not have covered them.
    - **Two edges self-declare a sanction no rule grants.** `application/services/play_poll_policy.py:68-71` documents itself as "the sanctioned narrow edge for reaching token storage from the application layer (the same shape the metric config provider uses)" — but `application-patterns.md` sanctions `MetricConfigProviderImpl` specifically, not token storage. `use_cases/import_play_history.py:299` does the same for `play_import_registry`. Either the rule is amended or the code grows a port; a docstring is not ratification.
    - **`application-patterns.md`'s bridge list is stale**: `workflows/engine/executor.py` is named as an approved infrastructure bridge but no longer imports infrastructure at all (it delegates to `workflows/context.py`).

    Open judgement calls, in rough order of severity: `interface/_shared/run_lifecycle.py` and `api/routes/settings.py` reach repositories **directly** from interface — the exact thing `interface-patterns.md` line 6 forbids, and unrelated to the credential carve-out; `application/chat/pending_actions.py` opens its own sessions and manipulates `DBPendingAction` rows; the `error_classification` cluster (4 edges) is a pure helper with no data access but still interface reaching sideways; `metric_registry` leaks one layer past its sanctioned home into `interface/`. Also flagged by the run: `api/deps.py`'s 4 credential imports were sanctioned as the same surface the named routes use, factored into a dependency module — reasonable, but the rule doesn't name it. Separately, `persistence/database/migrations/add_confidence_evidence.py` is an orphaned alembic revision (`down_revision = None`) referenced by nothing and invisible to the graph; it looks like dead code wanting deletion.
